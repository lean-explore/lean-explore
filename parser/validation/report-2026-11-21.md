# Four-corpus parser regression report

This run fixes the 56 Anthropic FLT main-theorem signature errors and the Mathlib source-range errors found during validation. It also improves generated-name resolution and adds an optional export of Lean's generated `simps` constants. Source-written declarations and inferred generated names have separate accuracy measurements.

## Verified source declarations

Anthropic's independent main-theorem extractor provides 29,511 reference declarations. The final Rust output matches every name, declaration kind and signature, including all [56 previously truncated signatures](flt-original-errors-2026-11-21.json). The error list retains their names and original truncation positions. This reference covers main theorems, not every declaration in the FLT repository.

The built Mathlib reference covers 8,056 of the 8,206 source modules. Within that scope, the Rust parser matches all 265,485 source-written reference declarations with exact ranges and selections. Authored precision is 265,827/265,827. The precision denominator also includes parser declarations whose reference classification differs from the authored-recall categories.

Two cached anonymous-instance ranges were stale. Their unchanged source module was recompiled under its original name in a separate artifact overlay. The old/new reference rows, source hash and command templates are preserved in the portable validation provenance; the local artifacts also retain the executed commands. No source edits or hand-adjusted reference positions were used to make the check pass.

Unverified signatures have parser recovery or unresolved grammar context in the reference tool. They are retained in the denominator and error artifacts. The strict clean-context gate therefore does not pass for the whole corpora. These figures establish conditional boundary agreement, not universal 100% parser accuracy.

## Generated names and `simps`

Generated-name precision is 30,410/30,833 (98.6281%). Generated-attribute recall is 25,568/48,874 (52.3141%). Every matched constructor, parent-projection and attribute-generated reference has exact ranges and selections. Miscellaneous generated constants and constants without ranges are outside this span check. These are different denominators: generated precision includes constructors and parent projections; the recall figure covers attribute-generated constants.

The source parser now reads `initialize_simps_projections` prefix settings for directly annotated structure types. This recovers 43 additional generated names. Translation fixes recover 873 more matching generated records: abbreviation matching now continues inside compound names, and `to_dual existing` registers namespace translations without emitting duplicate declarations.

Static `simps` extraction has the following results against the range-attributed Lean reference:

| Attribute | Recovered reference names | Correct emitted names |
|---|---:|---:|
| `simps` | 952/10,037 (9.4849%) | 952/983 (96.8464%) |
| `simps!` | 1,695/7,708 (21.9901%) | 1,695/1,750 (96.8571%) |
| Combined | 2,647/17,745 (14.9169%) | 2,647/2,733 (96.8533%) |

All 2,647 matched ranges and selections are exact. All 86 unmatched static `simps` candidate names are marked `approximate=true`; none are marked exact. The reference includes 37 internal constants, five of which are recovered statically.

Default `simps` expansion still depends on elaborated result types, coercions and recursive projection rules. The optional `export_generated.py` reads a built Lean environment's range dump and writes a separate semantic sidecar. This run exports 17,745 range-attributed `simps`/`simps!` constants: 10,037 `simps` and 7,708 `simps!`, including 37 internal constants. This includes 16,209 constants attributed to direct attributes and 1,536 to nested `(attr := ...)` configurations. One attribute can generate several constants.

The sidecar preserves Lean's names and positions and records source/reference hashes. Its provenance is `lean-environment`; its records are not counted as Rust-parser discoveries. The dump also contains 233,290 constants without ranges, which cannot be assigned to an attribute by this exporter. Two invalid range starts belong to unrelated `elementwise` constants and remain recorded in metadata.

## Optimizations

Increasing the output buffer from 8 KiB to 1 MiB reduced FLT JSON export time by 37.7% in two paired runs with reversed order. All four outputs were byte-identical. This measures export throughput on WSL/NTFS.

Serializing output in ordered batches of 1,024 files reduced median export peak RSS by about 9.7% in a separate paired experiment. The median time was about 2.7% slower, so this change is retained as a memory tradeoff. The later output-buffer experiment addresses export throughput separately.

Caching failed absolute-value lookahead removes repeated scanning of long signatures. A 49,188-byte stress source took 113.396 ms before the change and 0.124 ms after it, about 916.5 times faster. The complete declaration JSON, including the 49,180-byte signature, is identical before and after. This is an isolated worst case, not a corpus-wide speedup.

## Scope and reproduction

The parser indexes explicit `axiom` declarations and `proof_wanted`, along with source signatures and body ranges. It does not yet emit dedicated `sorry`/`admit` counts or transitive axiom dependencies. The latter need Lean's elaborated environment.

The [performance data](results-2026-11-21.json) records individual samples, export hashes and optimization experiments. The [Mathlib data](mathlib-2026-11-21.json) records the accuracy denominators and reference provenance.

Use the [validation guide](README.md) for context inputs, reference generation and benchmark commands. The [native syntax guide](SYNTAX.md) explains independent signature checks and their limits. File coverage, agreement with usable references, and recovery of elaborator-generated constants must be reported separately.
